### Understanding Our Vision System

It's important to understand that our vision system has two main parts:

**Limelight side:**

- The Limelight has an internal computer that does the majority of the computer vision processing. It finds specific data about what you've configured it to see (AprilTag positions, object detections, etc.). It then transmits that data to the rest of our robot for processing.

**RoboRIO / system core side:**

- Once we have the data from AprilTags, we do some filtering and manipulation of that data to get an accurate position of our robot. We then feed that information back into our code to help with tasks like aiming and autonomous routines.

### Things You'll Need to Change Depending on Your Limelight Configuration

Most of this won't apply to this lesson, but it's good to know what you'll actually need to change later!

#### `RobotContainer.java`, lines 80–81 (the main place)

`new LimelightWrapper("limelight-two", true)` and `new LimelightWrapper("limelight-five", true)`.

- The first argument is the hostname set in the Limelight's web UI. It has to match exactly, or NetworkTables reads will come back empty.
- The second argument, `isLL4`, should be `true` for an LL4 and `false` for an LL3 or LL3G.
- `isLL4` changes behavior in `LimelightWrapper`. The MT1 yaw measurement is only added when it's `true` (the `if (isLL4)` block in `updateLocalizationLimelight`). Some of the vision weighting also depends on it.

#### `RobotContainer.updateLocalization()`, lines ~253–267

- The pipeline indexes are hardcoded: pipeline 1 is the viewfinder, and pipeline 0 is the AprilTag pipeline.
- A replacement Limelight needs the same pipelines in those slots. Flash or copy the configuration onto it.
- The code calls `llMain` the main Limelight and `llBackup` the backup. If you swap which physical unit plays which role, change the names in the constructors (lines 80–81).

#### Settings That Live on the Limelight, Not in Code

- The camera pose relative to the robot (forward, side, up, roll, pitch, yaw) is set in the Limelight web UI. MegaTag needs it to be correct. A new mount or unit means remeasuring and re-entering it.
- The simulation has its own copy of the camera pose (see below).

#### `sim/RebuiltSimManager.java`, lines ~404–415 (simulation only)

- `CameraConfig("limelight-two", LimelightType.LL4, llMainMount)` and the same for `"limelight-five"`.
- Update the name, the `LimelightType` (LL3 or LL4), and the `Transform3d` mount pose. This keeps the simulation matching the real robot.
- Line 223 has `FUEL_LL_NAME = "limelight-one"` for the fuel camera, with type LL3.

### Part 2: Robot-Side Lesson

#### Configure and Calibrate Your Limelight

The Limelight you were given on the test chassis probably already has all of these things done. But I want you to do them again so you know how to do it yourself.

Simply follow the quick-start guide in the documentation. I've linked the LL4 quick start, but if you're using an LL3, follow that guide instead:

[Limelight 4 Quick-Start | Limelight Documentation](https://docs.limelightvision.io/docs/docs-limelight/getting-started/limelight-4)

Once that's all done, it's time to configure the pipelines. If you're doing AprilTags, read through the AprilTag pipeline documentation in the Limelight docs.

You want to be able to:

- See AprilTag recognition in the camera stream from at least 10 feet away.
- View where the robot thinks it is using MT1 when it sees two tags. Make sure it's close to where you actually are. If it's not, try to figure out why. If you can't, a more experienced programmer probably can.

**Hint:** Set the mode to dark mode, lower the sensor gain to one, keep the blue balance around the middle and the red balance a little higher than the middle, and keep everything else the same. Exposure is the only value you should need to play with if these other settings are configured as above!

## Bonus challenge: color pipeline

Do you have an LL3? In this case, you can optionally configure a color pipeline as well. You're going to make a new pipeline and detect a color with it.

1. Click **Enable user pipeline switching** in the Limelight dashboard.
2. Switch to a new pipeline.
3. Enable **Color / Retroreflective** as the pipeline type.
4. Select an object of your choice to track! I would recommend a colorful game piece from a past year.
5. Follow [Color Thresholding | Limelight Documentation](https://docs.limelightvision.io/docs/docs-limelight/pipeline-retro/color-filtering) to threshold and track your specific color. Look through the rest of the pages in this section as well, as they'll teach you how to be more specific in how you track colors!
6. Retrieve `tx` and `ty` from your Limelight. This can be done in code through the `LimelightWrapper` object we use to represent Limelight hardware. Then, log those values with AdvantageKit.
