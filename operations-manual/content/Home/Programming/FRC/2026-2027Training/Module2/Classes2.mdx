## Project 2: Arm Mechanism Subsystem

In this project, you will create a complete FRC robot mechanism: an arm subsystem.

This project will combine your Java knowledge with real robot programming concepts. You will create a subsystem that controls an arm using:

- 1 CTRE Kraken X60 motor (TalonFX)
- 1 CTRE CANcoder absolute encoder
- CTRE Phoenix 6 configuration
- Motion Magic position control
- AdvantageKit logging
- WPILib Commands

Unlike the previous project, this mechanism will use more advanced object-oriented programming concepts.

### You Will Practice

- Extending classes through inheritance
- Using packages
- Encapsulation with private variables and getter methods
- Enums with constructors
- Lambda expressions
- Returning commands from methods
- Hardware configuration

## Step 1: Create Your Subsystem

Create a new subsystem class called:

`ArmSubsystem`

Use the WPILib VS Code tools to create this class.

To create a new subsystem:

1. Right-click the folder where you want the class.
2. Select the WPILib option to create a new subsystem.
3. Follow the prompts.

Notice that VS Code automatically creates:

- The package declaration at the top of the file.
- The correct imports.
- The class structure.

The package declaration is the first line of the file:

```java
package frc.robot.subsystems;
```

Packages organize your code into different folders. As your robot becomes larger, packages prevent your project from becoming difficult to manage.

Your subsystem should extend:

`SubsystemBase`

This is an example of inheritance.

Your class is inheriting functionality from WPILib's `SubsystemBase` class. This gives your subsystem access to features that all robot subsystems need.

## Step 3: Configure the CANcoder

The CANcoder needs to be configured so that the motor can correctly understand the arm position.

Create a CANcoder configuration object called `eConfig`.

Configure:

```java
eConfig.MagnetSensor.AbsoluteSensorDiscontinuityPoint = -0.25;
```

This configures where the encoder's absolute position wraps around.

Use the CTRE documentation to understand what this setting does. Or, ask FEDSbot.

## Step 4: Configure the TalonFX

Create a TalonFX configuration object called `tConfig`.

Configure your motor using the following values:

```java
tConfig.MotorOutput.NeutralMode = NeutralModeValue.Brake;

tConfig.Slot0.kP = 0.0;
tConfig.Slot0.kD = 0.0;
tConfig.Slot0.kG = 0.0;
tConfig.Slot0.kS = 0.0;

tConfig.Slot0.GravityType = GravityTypeValue.Arm_Cosine;

tConfig.CurrentLimits.StatorCurrentLimit = 40;
```

Some of these values will need to be tuned later.

Use CTRE documentation to learn:

- How Slot0 gains work.
- What gravity compensation does.
- How Motion Magic works.
- How control requests are used.

## Step 6: Create Arm State Enum

Your arm has three positions:

- `FORWARD`
- `UP`
- `BACKWARD`

Create an enum inside your subsystem:

```java
public enum ArmState {

}
```

Each state should store an angle.

Your enum constructor should accept a rotation angle using WPILib Units.

Example concept:

```java
private final Angle angle;

ArmState(Angle angle){
    this.angle = angle;
}
```

WPILib uses `Angle` to represent angles.

You can create rotations using:

```java
Rotations.of(0.5)
```

### Your Job

1. Move the arm manually.
2. Read the CANcoder position.
3. Record the correct values.
4. Use those values for your enum states.

The arm should have approximately 180 degrees of movement.

**IMPORTANT:** Don't deploy this code to a robot (which you will do later) until you have measured correct angles for each of your states. These will not be predetermined; you'll measure them on a real robot.

Deploying incorrect values could cause some stuff to not work right, or to break. Be careful, and ask a lead if you're not sure about something!

## Step 7: Create Logging Getter Methods

Use AdvantageKit's `@Logged` annotation.

Your subsystem should contain getter methods for:

- Stator current (amps)
- Voltage
- Position (rotations)
- Velocity (rotations per second)
- Acceleration (rotations per second squared)

This allows you to inspect your subsystem data later in AdvantageScope.

## Step 9: Create Commands For Each Arm Position

Instead of creating commands everywhere, your subsystem can return commands.

Create methods like:

```java
public Command setStateCommand(ArmState state)
```

Inside the method, return:

```java
return new InstantCommand(() -> setState(state));
```

The `()->` is called a lambda expression.

A lambda is a short way of creating a function without naming it.

This:

```java
() -> setState(ArmState.FORWARD)
```

means:

"When this command runs, call `setState()` with `ArmState.FORWARD`."

You will see lambdas throughout FRC programming, especially when creating commands, callbacks, and event handlers.

### Bind Your Commands

| Controller Button | Arm Position |
|---|---|
| X | Forward |
| Y | Up |
| A | Backward |

Your bindings should call:

```java
armSubsystem.setStateCommand(ArmState.FORWARD)
armSubsystem.setStateCommand(ArmState.UP)
armSubsystem.setStateCommand(ArmState.BACKWARD)
```

If you have questions about command bindings or Xbox controllers, ask FEDSBot for help.
