## 🚚 Moving Day

In Modules 3 and 4, our robot lived in the **console**: the plain text box where `println` shows up. Programiz is great for that, but it has one big limitation: **there's no window**. Programiz can't draw shapes or listen to your arrow keys.

So we're packing up the robot and moving to a new home:

👉 **[OneCompiler: Java Swing](https://onecompiler.com/java-swing)**

OneCompiler runs your Java program on its server and **streams the window it creates right into your browser**. You get a real window with real arrow keys, and you still don't have to install anything.

How to use it:

1. Open the link above. You'll see some sample code already in the editor.
2. **Delete all of it** and paste in the code from this guide.
3. Press **Run**.
4. A window appears in the output area. **Click inside the window** so it knows you're talking to it, then press your arrow keys.

The good news: the single-file layout is the same as Programiz. `public class Main` goes on top, and `class Robot` (without `public`) goes underneath.

> 💡 **"Swing"** is the name of Java's built-in toolkit for making windows, buttons and drawings. That's why the compiler is called "Java Swing." It has nothing to do with playgrounds. 🛝

## Console vs. Event-Driven: The Doorbell 🔔

In Module 4, our game loop worked like this:

```java
while (true) {
    String input = scanner.nextLine();   // wait for the user...
    // ...then do something
}
```

That's like standing at your front door all day, **checking every second** to see if anyone's there. You're in charge, and you keep asking: "Anyone? Anyone? How about now?"

A windowed program works differently. It's like installing a **doorbell**. You tell Java, "**When** someone presses a key, **call this method** of mine." Then you go do other things. When the doorbell rings, Java runs your method.

This is called **event-driven programming**. An *event* is something that happens, like a key press, a mouse click or a window closing. Your job is to write the code that **reacts** to events.

The motto of event-driven code: **"Don't call us, we'll call you."** 📞

| Console program (Module 4) | Event-driven program (Module 5) |
|---|---|
| *You* write a loop that keeps asking for input | *Java* waits for input for you |
| `scanner.nextLine()` stops everything until Enter is pressed | Your `keyPressed` method runs whenever a key is pressed |
| Output is text only | Output can be a window, shapes and colors |

## 🛠 Exercise: Run Step 3

Here's **Step 3** of the robot game, combined into one file. (We added one line, `frame.setSize(400, 300);`, so the window isn't microscopic.) Don't worry about understanding it yet. The next lessons explain every line.

Paste it into OneCompiler, press **Run**, click the window, and press the arrow keys a few times.

```java
import java.awt.event.KeyEvent;
import java.awt.event.KeyListener;

import javax.swing.JFrame;
import javax.swing.SwingUtilities;

public class Main implements KeyListener {
    Robot robot;
    JFrame frame;

    Main() {
        robot = new Robot();

        frame = new JFrame();
        frame.setSize(400, 300);
        frame.setDefaultCloseOperation(JFrame.EXIT_ON_CLOSE);
        frame.addKeyListener(this);
        frame.setFocusable(true);
        frame.setLocationRelativeTo(null);
        frame.setVisible(true);
    }

    public static void main(String[] args) {
        System.out.println("Program started!");
        SwingUtilities.invokeLater(() -> new Main());
    }

    @Override
    public void keyPressed(KeyEvent e) {
        int keyCode = e.getKeyCode();

        switch (keyCode) {
            case KeyEvent.VK_UP:
                robot.moveUp();
                break;
            case KeyEvent.VK_DOWN:
                robot.moveDown();
                break;
            case KeyEvent.VK_LEFT:
                robot.moveLeft();
                break;
            case KeyEvent.VK_RIGHT:
                robot.moveRight();
                break;
        }
    }

    @Override
    public void keyReleased(KeyEvent e) {
        // Not used
    }

    @Override
    public void keyTyped(KeyEvent e) {
        // Not used
    }

}

class Robot {
    int x;
    int y;

    public void moveUp() {
        y = y - 1;
        System.out.println("Moving UP - New position: (" + x + ", " + y + ")");
    }

    public void moveDown() {
        y = y + 1;
        System.out.println("Moving DOWN - New position: (" + x + ", " + y + ")");
    }

    public void moveLeft() {
        x = x - 1;
        System.out.println("Moving LEFT - New position: (" + x + ", " + y + ")");
    }

    public void moveRight() {
        x = x + 1;
        System.out.println("Moving RIGHT - New position: (" + x + ", " + y + ")");
    }

}
```

You'll see an **empty gray window**, but press **→**, **→**, **↓** and the console prints:

```text
Program started!
Moving RIGHT - New position: (1, 0)
Moving RIGHT - New position: (2, 0)
Moving DOWN - New position: (2, 1)
```

The `Robot` class is the **exact same one** you built in Module 3. Only `Main` changed. That's the power of classes: we gave the robot a whole new way to be controlled without touching its blueprint.

### 😵 Nothing happens when I press keys!

1. **Click inside the window first.** Keys only go to the window that has *focus* (the one you last clicked).
2. Still nothing? Some browser setups don't pass focus to the frame itself. Try putting the key listener on the window's **content pane** instead. Replace the `frame.addKeyListener(this);` and `frame.setFocusable(true);` lines with these, and put them **after** `frame.setVisible(true);`:

```java
frame.getContentPane().setFocusable(true);
frame.getContentPane().addKeyListener(this);
frame.getContentPane().requestFocusInWindow();
```

3. Still stuck? Ask a mentor. That's what we're here for!
