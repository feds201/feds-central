## The Job Contract Analogy

Imagine applying for a job as a **lifeguard**. 🏊 To get the job, you sign a contract that says:

> "I promise I know how to **swim**, **blow the whistle**, and **do CPR**."

The pool doesn't care *how* you swim, whether it's freestyle or doggy paddle. It just needs to know that when there's an emergency, it can **call on you** and you'll do those three things.

An **interface** in Java is exactly that kind of contract. It's a list of methods that a class **promises** to have.

Java's `KeyListener` interface is the contract for "**I can react to keyboard keys.**" It lists three methods:

| Method | When Java calls it |
|---|---|
| `keyPressed(KeyEvent e)` | The moment a key goes **down** |
| `keyReleased(KeyEvent e)` | The moment a key comes back **up** |
| `keyTyped(KeyEvent e)` | When a key produces a **character** (like `a` or `?`, but not arrow keys) |

## The Real Code (Step 3)

### Signing: `implements`

```java
public class Main implements KeyListener {
```

This line says: "`Main` signs the `KeyListener` contract." From now on, Java **guarantees** that `Main` has all three methods. If you forget even one, the program won't compile.

That's why Step 3 has two methods that do nothing:

```java
@Override
public void keyReleased(KeyEvent e) {
    // Not used
}

@Override
public void keyTyped(KeyEvent e) {
    // Not used
}
```

A contract is a contract! You have to show up, even if all you do is stand there. 🧍 (The `// Not used` comment is a note for humans. Java ignores everything after `//` on a line.)

### `@Override`: "I'm filling in the contract on purpose"

You met `@Override` in Module 3 with `toString()`. It's the same idea here: it tells Java, "this method fills in a method from somewhere else." If you misspell the name, say `keyPresed`, Java will warn you that there's nothing to override. Without `@Override`, that typo would silently become a brand-new method that **nobody ever calls**, and you'd spend an hour wondering why your keys don't work. 😩

### Ringing the doorbell: `addKeyListener(this)`

```java
frame.addKeyListener(this);
```

This line hands Java the list of who to call when a key is pressed in the window. But who are we handing over? `this`!

In Module 3, `this` meant "**my** field." Here, `this` by itself means "**me, the whole object**." So the line reads:

> "Hey window, when a key is pressed, call **me**. I signed the KeyListener contract, so you know I have a `keyPressed` method."

Without this line, the window has no idea anyone cares about the keys, and your `keyPressed` method never runs.

### Figuring out which key: `KeyEvent`

When Java calls `keyPressed`, it hands you a `KeyEvent` object named `e`. It's like a little **delivery slip** 📦 describing what happened.

```java
@Override
public void keyPressed(KeyEvent e) {
    int keyCode = e.getKeyCode();

    switch (keyCode) {
        case KeyEvent.VK_UP:
            robot.moveUp();
            break;
        case KeyEvent.VK_DOWN:
            robot.moveDown();
            break;
        case KeyEvent.VK_LEFT:
            robot.moveLeft();
            break;
        case KeyEvent.VK_RIGHT:
            robot.moveRight();
            break;
    }
}
```

- `e.getKeyCode()` returns an **int**: a number that identifies which key was pressed.
- Nobody wants to memorize that the up arrow is `38`. So Java gives every key a **named constant**: `KeyEvent.VK_UP`, `KeyEvent.VK_W`, `KeyEvent.VK_SPACE`, and so on. `VK` stands for "**V**irtual **K**ey."
- Then it's the same `switch` you learned in Module 4. This time we switch on an `int` instead of a `String`.

| Key | Constant |
|---|---|
| ↑ ↓ ← → | `VK_UP`, `VK_DOWN`, `VK_LEFT`, `VK_RIGHT` |
| Letters | `VK_A` to `VK_Z` |
| Numbers | `VK_0` to `VK_9` |
| Spacebar, Enter, Escape | `VK_SPACE`, `VK_ENTER`, `VK_ESCAPE` |

## Imports: Borrowing Tools 🧰

```java
import java.awt.event.KeyEvent;
import java.awt.event.KeyListener;

import javax.swing.JFrame;
import javax.swing.SwingUtilities;
```

Just like `import java.util.Scanner;` in Module 4, these lines borrow tools from Java's library:

- `java.awt.event` is the **events** shelf: things that happen, like key presses.
- `javax.swing` is the **window** shelf: frames, panels, labels.

In Step 4, you'll see a shortcut: `import javax.swing.*;`. The `*` means "**borrow everything** on that shelf."

## The Starting Line: `invokeLater`

```java
public static void main(String[] args) {
    System.out.println("Program started!");
    SwingUtilities.invokeLater(() -> new Main());
}
```

Here's the short version. Swing has **one special helper** in charge of everything about the window. Think of it as the **one waiter** in a restaurant who's allowed to serve the windows. 🍽️ If anyone else tries to build a window, things can get mixed up.

`invokeLater` means "**Waiter, please do this job when you're ready.**"

The job itself is `() -> new Main()`. That odd arrow thing is called a **lambda**. It's a tiny, nameless method you can hand around like a sticky note. Read it as "**a job that does: `new Main()`**." The empty `()` means the job needs no inputs.

So the whole line reads: "Waiter, when you're ready, build a new `Main`." Building a `Main` runs its **constructor**, and the constructor builds the robot and the window.

> 💡 You'll see this exact `invokeLater` line at the bottom of almost every Swing program. It's fine to treat it as "the magic words that start a Swing app" for now.

### Main has a constructor too!

```java
Main() {
    robot = new Robot();
    frame = new JFrame();
    // ...set up the window...
}
```

Up until now, `main` did all the work. Now `main` just builds a `Main` object, and **`Main`'s constructor** does the setup. `robot` and `frame` are **fields** of `Main` (its backpack), so `keyPressed` can use `robot` later. Notice that a field can hold **any** type of object, not just `int` or `String`. Here they hold a `Robot` and a `JFrame`.

## 🙈 Common Oopsies

- **Leaving out one of the three methods.** You'll get an error like `Main is not abstract and does not override abstract method keyTyped(KeyEvent) in KeyListener`. Translation: "you broke the contract!" Add the missing method, even if it's empty.
- **Forgetting `frame.addKeyListener(this);`** The contract is signed, but nobody gave the window your phone number. Nothing happens when you press keys.
- **Forgetting to click the window.** Keys only go to the window with focus.
- **Misspelling a method name** without `@Override`, for example `keypressed`. It compiles but never runs. Use `@Override` so Java catches this.
- **Forgetting `break`** in a `case`. Pressing ↑ would move up **and** down! (Remember fall-through from Module 4.)
