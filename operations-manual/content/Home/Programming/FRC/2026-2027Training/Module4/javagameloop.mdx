## The Arcade Machine Analogy

An arcade machine doesn't play **one** game and then shut off forever. It runs a loop:

1. Wait for a player to press a button.
2. React to it.
3. Go back to step 1.

It does this **over and over**, all day long, until someone flips the power switch. 🔌

Almost every video game ever made works this way. It's called a **game loop**: *listen → react → repeat*.

## `while` Loops: A Quick Refresher

You met `while` loops in Module 1:

```java
int count = 1;

while (count <= 3) {
    System.out.println("Lap " + count);
    count++;
}
```

```text
Lap 1
Lap 2
Lap 3
```

Before each lap, Java checks the condition. If it's `true`, the body runs again. If it's `false`, the loop ends.

---

## `while (true)`: Loop Forever?!

Here's the heart of **Step 2**:

```java
while (true) {
    // ...
}
```

The condition is literally `true`, so it's **always** true, and the loop runs **forever**. 😱

That sounds like a bug, but for a game it's exactly what we want. We don't know ahead of time how many moves the player will make. Maybe 3, maybe 300. So we loop forever and give the player an **eject button** to get out.

## `break`: The Eject Button ⏏️

```java
break;
```

`break` instantly **jumps out of the loop**, and the program continues with the first line *after* the loop's closing brace. (You also saw `break` in `switch`, where it does the same job: "get out of here.")

## The Real Code (Step 2)

Here's **all** of Step 2, combined into one file for Programiz. You now know every single piece!

```java
import java.util.Scanner;

public class Main {

    public static void main(String[] args) {
        System.out.println("Program started!");

        Scanner scanner = new Scanner(System.in);

        System.out.println("Enter a direction:");
        Robot robot = new Robot();

        while (true) {
            System.out.println("f = forward | b = back | l = left | r = right  | x = exit");
            String input = scanner.nextLine();

            if (input.equals("f") || input.equals("b") || input.equals("l") || input.equals("r")) {
                robot.move(input);
            }
            else if (input.equals("x")) {
                System.out.println("Exiting program");
                break;
            }
        }

        scanner.close();
    }
}

class Robot {

    public void move(String key) {
        System.out.print(" ===== Robot is moving ");

        switch (key) {
            case "f":
                System.out.println("Forward =====");
                break;
            case "b":
                System.out.println("Back =====");
                break;
            case "l":
                System.out.println("Left =====");
                break;
            case "r":
                System.out.println("Right =====");
                break;
        }
    }

}
```

### Walkthrough 🚶

| Step | What happens | You learned it in |
|---|---|---|
| 1 | `import java.util.Scanner;` checks the Scanner out of the library | Imports and Scanner |
| 2 | Print "Program started!" | Module 1 |
| 3 | Plug in the microphone: `new Scanner(System.in)` | Imports and Scanner |
| 4 | Build **one** robot with `new Robot()`, **before** the loop | Module 3 |
| 5 | Start the game loop with `while (true)` | This lesson! |
| 6 | Print the menu, then **wait** for the player with `nextLine()` | Imports and Scanner |
| 7 | If it's a direction, press the robot's `move` button | Conditionals, Module 3 |
| 8 | The robot's `switch` picks the right message | Switch |
| 9 | If it's `x`, say goodbye and `break` out of the loop | This lesson! |
| 10 | Anything else? Ignore it, and the loop goes back to step 6 | Conditionals |
| 11 | After the loop: `scanner.close()` turns off the faucet | Imports and Scanner |

> 💡 **Why is the robot built *before* the loop?** If `new Robot()` were inside the loop, you'd build a brand-new robot every turn. Remember the "new TV every time you change the channel" problem from Module 3? Same idea. Build once, use many times.

> 💡 **Why is `String input` *inside* the loop?** Each turn needs a fresh answer from the player, so we read a new line every time around.

## Counters: Keeping Score 🧮

A **counter** is a variable that goes up each time something happens. It must be created **before** the loop, or it would reset to 0 every lap:

```java
int moves = 0;          // before the loop: start at zero

while (true) {
    // ...
    moves++;            // inside the loop: add one (same as moves = moves + 1)
}

System.out.println("Total moves: " + moves);   // after the loop
```

## 🔮 Predict the Output

```java
public class Main {

    public static void main(String[] args) {
        int energy = 10;
        int laps = 0;

        while (true) {
            energy -= 3;
            laps++;
            System.out.println("Lap " + laps + ", energy " + energy);

            if (energy < 3) {
                System.out.println("Out of gas!");
                break;
            }
        }

        System.out.println("Finished " + laps + " laps");
    }
}
```

Answer:

```text
Lap 1, energy 7
Lap 2, energy 4
Lap 3, energy 1
Out of gas!
Finished 3 laps
```

## 🙈 Common Oopsies

- **A `while (true)` with no `break`.** The program never ends! In Programiz, press **Stop** to escape.
- **Creating the counter inside the loop.** `int moves = 0;` inside the loop resets it every lap, so it's never more than 1.
- **Building the robot (or the Scanner) inside the loop.** You get a brand-new one every lap, and the old one's memory is lost.
- **Closing the Scanner inside the loop.** The next `nextLine()` crashes. Close it **after** the loop.
- **Forgetting that `break` inside a `switch` only exits the `switch`, not the loop.** That's one reason Step 2 uses an `if` (not a `switch`) to check for `x`.
