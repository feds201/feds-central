## The Library Analogy 📚

Java comes with **thousands** of ready-made classes that other programmers already wrote for you. They're organized into **packages**, like books sorted onto shelves in a giant library.

A few classes, like `String` and `System`, sit right on your desk, so you can use them anytime. But most classes are on the shelves. To use one, you have to **check it out** first. That's what `import` does:

```java
import java.util.Scanner;
```

Read it like a library address: "Go to the `java` section, find the `util` (utilities) shelf, and grab the book called `Scanner`."

> 💡 `import` lines always go at the **very top** of the file, above `public class Main`.

You've actually seen this line before! **Step 0's** `Main.java` starts with `import java.util.Scanner;`. Step 0 never *uses* the Scanner, though. It just checked out the book and left it on the desk. 📖

## The Microphone Analogy 🎤

A `Scanner` is like a **microphone** plugged into your keyboard. Once you set it up, you can ask it, "What did the user just say?"

Here's how **Step 2** sets one up:

```java
Scanner scanner = new Scanner(System.in);
```

This should look familiar from Module 3! It's the same pattern as `Robot robot = new Robot();`:

| Piece | Meaning |
|---|---|
| `Scanner` | The **type** (the class we imported) |
| `scanner` | The **variable name** (lowercase, by convention) |
| `new Scanner(...)` | Build a brand-new Scanner object |
| `System.in` | The **argument** to its constructor: "listen to the keyboard" |

`System.out` is where your program **talks** (you've used it in every `println`). `System.in` is where your program **listens**. Out = mouth 👄, in = ears 👂.

---

## Listening: `nextLine()`

```java
String input = scanner.nextLine();
```

`nextLine()` is a method that **returns** a `String`, just like the vending machine methods from Module 3. Here's what happens when Java reaches this line:

1. The program **pauses** and waits. ⏸️
2. The user types something and presses **Enter**.
3. Everything they typed on that line comes back as a `String`, which gets stored in `input`.

Your program will wait *forever* for the user to press Enter. It's very patient. 🐢

---

## Turning Off the Faucet: `close()`

```java
scanner.close();
```

When you're done listening, you `close()` the Scanner. Think of it like turning off the faucet when you're done washing your hands. 🚰 The program usually works without it, but leaving things running is sloppy, and VS Code will even warn you about a "resource leak."

> ⚠️ Only close the Scanner when you're **completely** done reading input. After `close()`, you can't read anything else.

## 🔮 Predict the Output

The user types `Chompy` and presses Enter. What prints?

```java
import java.util.Scanner;

public class Main {

    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);

        System.out.println("What is your robot's name?");
        String name = scanner.nextLine();

        System.out.println(name + " says hi!");
        System.out.println(name.length() + " letters long");

        scanner.close();
    }
}
```

Answer:

```text
What is your robot's name?
Chompy says hi!
6 letters long
```

(In Programiz you'll also see `Chompy` on its own line, where you typed it.)

## 🙈 Common Oopsies

- **Forgetting the import.** Without `import java.util.Scanner;`, Java says `cannot find symbol: class Scanner`. It's like asking for a book you never checked out.
- **Putting the import in the wrong place.** It goes at the top of the file, not inside a class or method.
- **Making a new Scanner every time you read.** Create **one** Scanner and reuse it. One microphone is plenty.
- **Using `scanner` after `close()`.** You'll get an error. The faucet is off!
- **Clicking Run and wondering why nothing happens.** The program is waiting for you to type in the output panel.
