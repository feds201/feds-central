## The Remote Control Analogy 📺

Think of a TV remote. It has buttons: **Power**, **Volume Up**, **Channel Down**. Each button does one specific job, and you can press any button **as many times as you want, whenever you want**.

**Methods are the buttons on your robot's remote control.**

The constructor is different. It runs **once**, when the robot is born, and then never again. You can't "re-birth" the same robot. 🐣 So if we want the robot to move *every* time we ask, a constructor is the wrong tool. We need a method.

---

## The Real Code: From Step 0 to Step 2

Here's how the **Step 0** robot was written. All of its moving code was stuffed into the **constructor**:

```java
class Robot {

    Robot(String key) {
        System.out.print("  Robot is moving ");

        switch (key) {
            case "f":
                System.out.println("Forward");
                break;
            case "b":
                System.out.println("Back");
                break;
            case "l":
                System.out.println("Left");
                break;
            case "r":
                System.out.println("Right");
                break;
        }
    }

}
```

The problem is that to move three times, you'd have to build **three whole robots**:

```java
new Robot("f");
new Robot("l");
new Robot("f");   // 3 robots?! We only wanted one robot to move 3 times!
```

That's like buying a new TV every time you want to change the channel. 📺📺📺

So in **Step 2**, the code moved into a **method** named `move`:

```java
class Robot {

    public void move(String key) {
        System.out.print(" ===== Robot is moving ");

        switch (key) {
            case "f":
                System.out.println("Forward =====");
                break;
            case "b":
                System.out.println("Back =====");
                break;
            case "l":
                System.out.println("Left =====");
                break;
            case "r":
                System.out.println("Right =====");
                break;
        }
    }

}
```

(Don't worry about `switch` yet. You saw it in Module 1, and Module 4 covers it in detail. For now, read it as "pick a line based on which letter `key` is.")

Now **one** robot can move as many times as we like:

```java
Robot robot = new Robot();   // build it ONCE
robot.move("f");             // press the button
robot.move("l");             // press it again
robot.move("f");             // and again!
```

```text
 ===== Robot is moving Forward =====
 ===== Robot is moving Left =====
 ===== Robot is moving Forward =====
```

> 💡 **Wait, `new Robot()` works with no constructor?** Yes! If you don't write *any* constructor, Java quietly gives you an empty one for free, called the *default constructor*.

## Anatomy of a Method

```java
public void move(String key) {
    // the method's body: the code that runs when you press the button
}
```

| Piece | What it means |
|---|---|
| `public` | Anyone can press this button. (More on this in the next lesson.) |
| `void` | The **return type**. `void` means "I do something, but I don't hand anything back." |
| `move` | The method's **name**. Use a verb! Methods *do* things. |
| `(String key)` | The **parameter**: an input the method needs to do its job. |
| `{ ... }` | The **body**: the code that runs each time the method is called. |

### Calling a method: the dot

```java
robot.move("f");
```

Read the `.` as **'s**: "robot**'s** move button, with the input `"f"`." The value you pass in (`"f"`) is called an **argument**. Inside the method, it shows up in the parameter variable `key`.

---

## Parameters: Placing Your Order ☕

A parameter is like your order at a coffee shop. The barista (the method) knows *how* to make drinks, but needs you to say *which* one:

```java
public void makeDrink(String size, String flavor) { ... }

barista.makeDrink("large", "hot chocolate");
```

- Multiple parameters are separated by **commas**.
- Arguments go in the **same order** as the parameters. `makeDrink("hot chocolate", "large")` would give you a very confused drink.
- The **types must match**. If the parameter is an `int`, you can't pass `"three"`.

## Return Values: The Vending Machine 🥤

Some methods just *do* something, like printing or moving. Their return type is `void`.

Other methods **hand something back**, like a vending machine. You press a button, and a snack comes out. To do that:

1. Replace `void` with the **type** of thing being returned.
2. Use the keyword `return` to hand it back.

```java
class Robot {

    public int countWheels() {
        return 4;
    }

}
```

When you call it, you can **catch** the returned value in a variable:

```java
int wheels = robot.countWheels();
System.out.println("My robot has " + wheels + " wheels");
```

```text
My robot has 4 wheels
```

In Step 4 of our game, the robot has methods like `getX()` and `getY()` that return its position. You'll write those in the next lesson.

> 💡 `return` also **ends** the method immediately. Any code after a `return` in the same block never runs.

## 🔮 Predict the Output

```java
public class Main {

    public static void main(String[] args) {
        Robot bot = new Robot();
        bot.beep(3);
        int answer = bot.addPoints(10, 5);
        System.out.println("Score: " + answer);
    }
}

class Robot {

    public void beep(int times) {
        System.out.println("Beeping " + times + " times");
    }

    public int addPoints(int a, int b) {
        return a + b;
    }

}
```

Answer:

```text
Beeping 3 times
Score: 15
```

## 🙈 Common Oopsies

- **Forgetting the parentheses.** `robot.move;` is wrong. Even with no arguments, you need `()`: `robot.spin();`
- **Returning nothing from a non-void method.** If you promise `int`, you **must** `return` an int.
- **Returning something from a `void` method.** A `void` method can't `return 5;`.
- **Calling a method on the class instead of the object.** `Robot.move("f")` is wrong. Press the button on *your* robot: `robot.move("f")`.
- **Wrong argument type or count.** `move()` and `move(5)` won't compile when the method needs one `String`.
